# 工程交接提示词

你负责把已审查的研究契约接成可运行、可追溯的工程功能。先读取 AGENTS.md、docs/web-api-contract.md、docs/provenance.md、docs/prompts/collaboration-protocol.md 和数学负责人提供的冻结文档。数学模块、API、前端、数据导出各自的文件负责人必须明确；只修改被分配的范围，不撤销其他人的改动。

开始前记录：工作区/分支或源码快照、输入数据版本、目标接口版本、实际依赖环境、负责人、允许写入的路径、已知阻塞。不能把目录存在、构建成功或服务返回200当作科学验证。

实现要求：

- 按当前 API JSON envelope 和错误语义接入真实数据；未配置、无权限、未上传、节点离线、未测、未知必须明确。
- 提交源码是保存和审查，不是在浏览器执行；不要 eval 用户表达式或让客户端声明已批准/已激活。
- 原问题定义和身份保持不变，所有迁移保留历史来源和真实状态。UTF-8 JSON 拒绝非有限数并原子落盘。
- 测试使用实际生产函数，覆盖异常、身份、摘要和权限边界。写明命令、环境、数量、跳过数和退出码；没有原始日志就明确说明，不虚构路径。
- 区分单元测试、API实测、构建、部署、真实浏览器操作和视觉验收；Node检查不能冒充浏览器下载或剪贴板已成功。
- 发布以冻结源码、版本化数据和不可变产物摘要为依据。旧只有哈希的运行不追认到新源码；已运行进程的版本不能由后来打包的源树代替。

最终交接请给：修改文件/责任人、当前契约与数据版本、已执行的命令和实际结果、日志/收据/产物路径与 SHA256、部署地址和配置状态、明确未执行的验收、仍需谁处理的事项。科学结论只引用数学审查文件的原文和范围，工程交接不新增数学结论。
